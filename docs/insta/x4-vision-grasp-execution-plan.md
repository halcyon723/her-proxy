# X4 视觉引导抓取执行计划书（软件绕行路线）

> 最终目标：**相机看到桌面物体 → 识别并定位 → 把位置传给机械臂 → 机械臂自动抓取**，一次完整的视觉引导 pick-and-place。
> 本计划书是 `x4-sdk-integration-plan.md`（路线决策）与 `insta360-x4-integration-guide.md`（故障记录）之后的**执行层文档**：按阶段推进，每阶段有判据，通过才进下一阶段。
> 路线基线（2026-08-29 定）：X4 无法 usbipd 直通 WSL（固件描述符畸形，见集成文档故障记录），采用 **Windows 采集 + HTTP 送帧 + WSL 控制** 的软件绕行架构；机械臂 SDK 仅有 Linux wheel，控制必须留在 WSL。

---

## 1. 目标链路与总体架构

```
[Windows]                                [WSL Ubuntu-24.04 / conda panthera]
X4 (UVC, USB摄像头模式)
  └─ x4_frame_server.py (OpenCV 抓帧)
       ├─ GET /frame.jpg  ──HTTP──→  x4_sdk_bridge.py::capture_frame()
       └─ GET /status                 └─ X4SdkCamera（既有委托机制，零改动）
                                          └─ vision_grasp 流水线
                                               ├─ perception.py 检测（像素 bbox）
                                               ├─ grasp_geom.py 像素→射线→桌面平面→基座系 3D
                                               │    （内参 calib_x4.yaml + 手眼 handeye_x4.yaml）
                                               ├─ 安全区检查（safe_box，已实测收敛）
                                               └─ IK → moveJ 预抓取 → 前倾下压 → 闭爪 → 抬升 → 放置
                                                    └─ hightorque_robot SDK（仅 Linux）
```

端口约定：取帧服务 **8200**（Windows 侧），多模态模型服务 8100，数字孪生 Demo 5001，远程指令 9000（均已避开）。

### 路线总纲：三级视觉递进，最大化复用固定抓取闭环

已打通的「固定位置稳定抓取」是最大的现成资产——执行层（前倾接近、过闭合、抬升、平稳放置）与安全限幅全部验证过。因此视觉按三级递进接入，**前两级几乎不需要标定**：

| 级别 | 视觉角色 | 复用内容 | 额外需要 |
|---|---|---|---|
| V1 视觉触发 | 判断「物体是否在固定抓取点」→ 触发回放 | 精炼轨迹 + 回放接口全部照搬 | 仅检测（无需任何标定） |
| V2 视觉偏移 | 检测目标位置 → 平移轨迹到新位置 | 轨迹结构 + 6D IK 工具链 | 局部像素→平面标定（少量点，可用机械臂自动采） |
| V3 视觉定位 | 任意位置几何抓取 | 流水线全部 + 前两级经验 | 内参 + 手眼标定（原 S4） |

V1/V2 各自都是可交付的独立里程碑（演示、比赛、验收都能用），不成功不阻塞下一级。

### S1 Windows 取帧服务（0.5 天）

新建 `robot-app/vision_grasp/x4_frame_server.py`：
- OpenCV `VideoCapture`（dshow 后端）打开 `Insta360 X4`，MJPG 模式，目标 2880×1440@30；
- 内置 HTTP 服务（标准库，不引第三方）：`GET /frame.jpg`（最新帧 JPEG）、`GET /status`（分辨率/帧率/累计帧数/掉帧计数）；
- 帧缓冲只留最新帧；取帧失败显式置 503，禁止返回旧帧；
- 命令行参数：`--index/--width/--height/--port`（默认 8200）、`--device-name`；
- Windows 防火墙放行 8200（仅专用网络）。

**判据**：浏览器访问 `http://localhost:8200/frame.jpg` 出图；连续 300 秒 `/status` 无掉帧中断；记录实际出流分辨率与视野形态（全景 2:1 还是单镜头）回填本文档 §5。

### S2 WSL 取帧桥接（0.5 天）

新建 `robot-app/vision_grasp/x4_sdk_bridge.py`：
- 模块级 `capture_frame() -> BGR ndarray`：GET `http://<host>:8200/frame.jpg`，超时 3s，失败抛 CameraError（含重连提示）——与 `x4_camera.py` 的 VIS-005 约定一致；
- `open()`：GET `/status` 探活；`close()`：空实现；
- 宿主 IP 从 `/etc/resolv.conf` nameserver 解析，可被环境变量 `X4_FRAME_SERVER` 覆盖。

**判据**：WSL 内 `python -c "import x4_sdk_bridge; print(x4_sdk_bridge.capture_frame().shape)"` 输出真实帧尺寸；Windows 侧重启服务后 WSL 自动恢复取帧。

### S3 感知服务接入（0.5~2 天，视模型而定）

- 先用 `perception.py` 的 mock 模式跑通 dry-run（零依赖验证链路）；
- 再部署真实多模态检测服务（Windows GPU，FastAPI，POST /predict 返回 bbox）——模型由团队提供时接入；约定与集成文档 Phase 1 一致。

**判据**：dry-run 全链路打印出检测 bbox → 平面交点 → 基座系坐标，数值量级合理（x 0.2~0.55、y ±0.27 内）。

### S4-V1 视觉触发固定抓取（0.5 天，零标定）

视觉只回答一个问题：**「目标物体是否出现在固定抓取点附近的 ROI 里」**（检测 bbox 中心落在预设 ROI 内即通过）：
- 新增小脚本（建议 `vision_trigger_grasp.py`）：取帧 → 检测 → ROI 判断 → 触发既有回放接口（`/api/replay/start`）；
- 物体不在位/检测失败 → 不动，显式报告；
- 轨迹、夹爪事件、安全限幅全部复用现有实现，一行不改。

**判据**：物体放在固定点 → 视觉确认 → 机械臂完整执行已验证的抓取-搬运-放置；拿走物体 → 机械臂不动。这就是第一个「视觉引导抓取」演示，**预计 S1+S2+S3+V1 共 2~3 天即可达成**。

### S4-V2 视觉偏移抓取（1 天，小范围泛化）

物体可放在固定点周围小范围（建议 ±8 cm）任意位置：
- **局部标定（免棋盘）**：物体依次摆在固定点及其周围 4~6 个已知偏移位（用尺量），记录检测 bbox 中心像素 → 拟合像素→平面毫米仿射映射（小范围透视可忽略）；
- **轨迹平移**：检测偏移量（像素→mm）后，把精炼轨迹的接近/抓取段按偏移量用既有 6D IK 重解（与抬升段生成同套路），搬运/放置段不变；
- 偏移超出标定范围或 IK 失败 → 回退到固定点模式报错，不盲抓。

**判据**：固定点 ±8 cm 内随机放置 10 次，成功抓起 ≥ 8 次；越界放置拒绝执行。

### S5-V3 全量标定泛化（1~2 天，任意 safe_box 位置）

原计划 S4 完整版，目标是从「固定点+小偏移」扩展到安全区任意位置：

1. **成像形态先固定**（S1 实测结果决定）：优先单镜头档；若仅全景档，固定同一裁切/投影方式，之后不再更改；
2. **内参标定**（`calib_x4.yaml`）：棋盘格 9×6、25mm，相机固定不动移板，15~20 姿态，`cv2.fisheye.calibrate`；判据 rms ≤ 1.0 px（若压缩画质导致不达标，放宽判据须先确认并记录）；
3. **手眼标定**（`handeye_x4.yaml`）：相机上腕部支架后，标定板固定桌面，12~20 个差异位姿采 `T_base_tool`（FK）+ solvePnP，`cv2.calibrateHandEye`；
4. **触点验证**：3 个不同角点，预测位置 vs 夹爪实际到达，平均误差 ≤ 5 mm；
5. 之后接入 `run_grasp.py --mode geometric` 几何模式全流程。

**判据**：两个 yaml 产出 + 触点误差 ≤ 5 mm + 安全区内随机位置抓取成功。注：手眼标定需相机完成腕部安装；未安装前 V3 不启动（V1/V2 用桌面固定相机即可，无需装机）。

### S6 全链路联调与收尾（0.5~1 天）

- dry-run（不动臂）→ 仿真（`backend.sh --demo`）→ 真机；
- 真机首跑规则：只执行"到目标上方 5cm 即停"；一人在急停旁监护；
- 动作序列遵守既有结论：**前倾接近（俯仰 15~47°）+ 过闭合夹紧 + 抬升 12cm + 压低 1cm 放置**，速度 ≤0.3（接近）/0.5（搬运）rad/s，力矩 30%。

**判据**：真机完成一次完整抓取-搬运-放置，全程无安全中止。

### S7 收尾固化（0.5 天）

- `config.yaml` 定稿（camera.source=x4_sdk、table 平面实测值、grasp 参数）；
- 帧服务开机自启（可选，任务计划程序）；
- 采集-训练回路（collect/train_grasp_policy）用真帧冒烟，为后续策略模式铺路。

## 4. 安全红线（全程有效，写死不变）

1. 目标点必须落在实测 safe_box 内，越界立即中止；
2. 速度/力矩限幅按 config.yaml 强制生效，任何模式不得突破；
3. 取帧失败/检测失败/IK 失败/标定缺失 → 显式报错中止，禁止静默继续；
4. 真机动作首次执行前必须人工确认；下降段一律先到预抓取高度悬停。

## 6. 难度评估（回答"这个难吗"，含三级路线后修正）

**总体：比原评估再降一档——固定抓取闭环把最难的执行层提前解决了。**

| 环节 | 难度 | 说明 |
|---|---|---|
| S1/S2 取帧链路 | ★☆☆ 低 | 成熟组件拼装，今天已验证 Windows 侧相机完好，半天级 |
| S3 物体检测 | ★★☆ 中 | 现成多模态模型+提示词即可定位桌面物体，bbox 精度要求仅厘米级 |
| **S4-V1 视觉触发** | ★☆☆ 低 | 检测结果只需判断「在不在 ROI 里」，轨迹零改动，零标定 |
| **S4-V2 视觉偏移** | ★★☆ 中 | 局部仿射标定 + 既有 6D IK 平移轨迹，工具链现成 |
| S5-V3 全量标定 | ★★★ 中高 | 唯一真正的难点（单目无深度，精度全靠两份标定）；但有了 V1/V2 兜底，它变成「锦上添花」而非「卡脖子」 |
| S6 联调 | ★☆☆ 低 | 执行层已在固定抓取中充分验证，只剩视觉入口的联调 |

**已提前拆掉的雷**：腕部无法竖直抓取（已改前倾）、示教轨迹拖地夹不紧（已精炼验证）、相机直通不兼容（已绕行）、**执行层抓取可靠性（固定位置已稳定复现）**。

**修正后结论：预计 2~3 个工作日达成 V1（首个视觉引导抓取演示，零标定）；再 1~2 天到 V2（±8cm 泛化）；V3 全量泛化按腕部装机进度另计。整条路线不再存在卡脖子环节，每级都有独立交付物。**
